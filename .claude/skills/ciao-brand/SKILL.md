# Ciao Brand

Ciao is a Libyan booking marketplace for chalets, estirahas and wedding halls.
Premium, photography-first. Two rules sit above everything else in this file:

1. **Light first.** Cream is the default ground. Dark is a real, supported theme
   that a guest chooses (or inherits from their phone at dusk) — not the default.
2. **Arabic first.** Arabic is the primary language, not a translation. Every
   rule here has to survive being set in Arabic, read right-to-left, on a phone.

Where this file and the code disagree, say so rather than silently following
either. The open questions are listed at the bottom.

## Logo

**Design v7: an orange teardrop pin with a white checkmark, and CIAO in
capitals beside it.** It replaced the drawn lowercase `ciao` wordmark outright.
There is one logo and this is it.

- **Never redraw it, and never re-set the word in a font to match a
  screenshot.** This has gone wrong twice. Use `components/logo.tsx`, which
  carries the artwork inline.
- **The pin never inverts.** On cream and on navy alike it stays orange with a
  white check — a solid shape carries its own contrast. Only the word changes:
  navy `--logo-ink` on light, cream on dark.
- **The pin always leads**, in Arabic too. The component forces `ltr`. A logo is
  a picture, not a sentence.
- **One size.** `logo.tsx` has no `size` prop on purpose.
- App icons are **the pin alone**, generated by `scripts/build-icons.py`. Run it
  after any change to the component; it fails if the three app copies drift.

## Colour

Every colour resolves through a token in `packages/shared/styles/tokens.css`.
Never hard-code a hex except on a photograph (see RTL/photo rule below).

### Light — the default

| Role | Token | Value |
|---|---|---|
| Page ground | `--sand` | `#fdf7ec` |
| Cards / surfaces | `--surface` | `#ffffff` |
| Primary ink | `--sea` | `#0d1b2a` |
| Secondary ink | `--muted` | `#5a4832` |
| Tertiary ink | `--faint` | `#7a6a52` |
| Brand accent | `--amber` | `#e8641b` |
| Deep accent | `--amber-dark` | `#b84a10` |
| Link | `--link` | `#9a5f0a` |
| Borders | — | `#dcd2c3` |

### Dark

| Role | Token | Value |
|---|---|---|
| Page ground | `--sand` | `#0d1b2a` |
| Cards / surfaces | `--surface` | `#1a2f45` |
| Primary ink | `--sea` | `#f5eedd` |
| Brand accent | `--amber` | `#e8641b` — does not change |
| Link | `--link` | `#dca55a` — lighter than the accent on purpose |

**Contrast is measured, not eyeballed.** This palette has shipped a 4.41:1 badge
and a 3.11:1 link before. Body text needs 4.5:1, large/bold 3:1, non-text edges
3:1 — against the *composited* background actually rendered, not the nominal
token.

Two measured facts worth carrying:

- White on `--amber` is **3.35:1** — fails for small text. Where white sits on
  orange at body size, use `--amber-dark` (5.22:1).
- The accent is **not** a text colour. Links use `--link` for this reason.

## Typography

**Almarai is the primary face, because the primary language is Arabic.**

| Role | Face |
|---|---|
| Arabic body and UI | **Almarai** — on the critical path |
| Wordmark, celebratory headlines | **Baloo Bhaijaan 2** |
| Latin companion | **Inter** |

Inter has **no Arabic coverage**. Never specify it as the only face, and never
remove Almarai from a stack — doing so renders the Arabic app in fallback
Tahoma. Latin-only stacks are a bug here, not a simplification.

Arabic runs wider and taller than English at the same size. Test every layout
with real Arabic strings, not lorem.

## RTL / Arabic

Arabic-first means RTL is the default case, not the edge case.

- Use **logical properties everywhere**: `start`/`end`, `ms-`/`me-`, `ps-`/`pe-`.
  Never `left`/`right` for anything that should flip.
- Icons and navigation must work in both directions. Avoid directional glyphs
  that do not flip naturally.
- **The logo does not flip.** Nor do numerals-with-units in a price pill.
- Anything drawn outside React — a map marker, a canvas label — has to state its
  own `dir`, because it sits outside the document's direction.
- Prefer symmetric, centred layouts where the choice is free.

## Components

### Verified badge

- **Dark translucent pill, white checkmark, white text.** Not orange — orange is
  the rating.
- Overlaid on the venue photograph, **top-start** corner (so it flips in Arabic).
- Always shown on a verified listing.

### Rating badge

- **Orange pill**, white star and text: `★ 4.95 (52)`.
- Overlaid on the photograph, **top-end** corner, opposite the verified badge.

### Listing card

- Radius **20px** (`rounded-bubble`); the photo is roughly **70%** of the card.
- Body padding 12–14px mobile, 16–20px desktop.
- Subtle shadow on light, subtle border on dark.
- Title in primary ink; **price in orange**; location in secondary ink with a
  pin glyph.

### Chips and buttons

- Pills are `999px` (`rounded-full`).
- **Active filter chip: orange fill.** Inactive: neutral surface with a border.
- **Primary CTA: orange fill, navy text** (`Book Now`, `Sign In`).
- Chips sitting on a photograph do **not** follow the theme — a photo is the
  same picture in both themes. See `.chip-on-photo`.

## Layout

### Mobile (390px)

- Single column, full-width cards.
- Hero occupies **60%+ of viewport height** — use `min-h-[60svh]`, not `vh`,
  or a collapsing address bar pushes the search control below the fold.
- Map screen carries a **bottom card strip**: horizontally scrollable venue
  previews, ~280px wide, snap scroll. Tapping a pin selects its card and back.

### Desktop (1440px)

- Top nav: logo start, search centre, account end.
- Listing grids **3 across**.
- Listing detail is a **split**: gallery ~60%, info panel ~40% with a sticky CTA.
- Map screen is **map + a scrollable venue sidebar**, not a bottom strip.
- Full footer, links in columns.

### Photography

- Hero photos full-bleed wherever possible; never a thumbnail as the primary
  visual. All venue photography is professionally shot — the UI frames it.
- Frosted glass / semi-transparent panels for controls over photos.
- The home hero carries **no scrim** (founder direction): legibility comes from
  `.type-on-photo`, not from dimming the picture. Re-run
  `tools/photo-contrast.mjs` after changing hero imagery — a white sky is the
  frame that breaks it.

## Mapbox

The map is the one surface whose **tiles do follow the theme**. Pins do not.

### Light

- Base `mapbox://styles/mapbox/light-v11`, re-pointed warm.
- Land `#f5edd8`, water `#c4b9a0`, roads `#d4c9b5`, labels `#0d1b2a`.

### Dark

- Base `mapbox://styles/mapbox/dark-v11`.
- Land `#121218`, water `#0a0e1a`, labels `#f5f2eb`.
- **Orange road glow**: `line-color #e8641b`, opacity ~0.4, `line-blur` 2–4. On a
  near-black ground the road network is the only thing that says which strip of
  coast this is.

Palette is applied by walking the style in `map-mapbox.tsx`, deliberately not by
publishing a hosted style in a Mapbox account — a hosted style is a second home
for the brand that drifts from `tokens.css`.

### Pins

- An **orange circle with a white check** — the logo pin echoed — joined to an
  **orange price pill**: `1,200 LYD`.
- Selected state is brighter, not merely a different hue.
- Approximate locations only. A venue with no coordinates gets **no pin, ever**.
- Default zoom 11–13, centred on the Tripoli coast.

## Spacing and radius

- Spacing: **4 / 8 / 12 / 16 / 24 / 32**.
- Radius: sm 8, md 12, lg 16, **card 20** (`rounded-bubble`), pill 999.

## Screens

Six, each drawn for mobile (390) and desktop (1440), in light and dark:

1. **Login** — full-bleed photo, frosted form, social sign-in
2. **Home** — hero, search overlay, category tiles, featured venues
3. **Search results** — filter chips, result count in orange, listing cards
4. **Listing detail** — gallery, spec chips, About, sticky Book Now
5. **Map search** — themed map, pin + price markers, card strip / sidebar
6. **Photo gallery** — immersive dark lightbox in *both* themes, counter,
   thumbnail strip

## Open questions — do not guess these

- **Type scale.** The design uses 11/13/15/19/24 (mobile) and 12/14/16/18/28/40
  (desktop). The code uses Tailwind's defaults, and four of those sizes do not
  exist in it. Reconciling means extending `fontSize` and migrating ~500 usages,
  or accepting Tailwind's scale. Not yet decided.
- **The dark ground.** The design file's dark is neutral (`#121218` / `#1C1C24`);
  the shipped dark is navy (`#0d1b2a` / `#1a2f45`). Not yet decided.
- **The verified badge in code** is currently orange (`bg-amber-dark`) and this
  file says dark. One of them has to move.
- **Off-scale spacing.** ~72 usages sit outside the scale above (`p-5`, and 6px
  half-steps). Either widen the scale or migrate them.
